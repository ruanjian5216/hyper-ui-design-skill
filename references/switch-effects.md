# Switch：完整液态交互基线

本文件对应包内 HyperSwitch.kt / HyperSwitchMotion.kt / HyperSwitchGestures.kt，以及 hyper_switch.dart / hyper_switch_motion.dart。当前设计结合 HyperUI 共用玻璃皮肤与参考 Toggle 的完整运动链路，不能只实现“玻璃滑块 + 普通位置弹簧”。

## 尺寸与布局

本包基线为轨道52×32、静止滑块22×22、初始偏移5、行程20。形状使用与尺寸相适配的 Capsule（22×22时为圆）。不能因美化删除扩张、缩小点击区域或裁切超出轨道的绘制。外部目标有明确尺寸要求时由用户指定，不自动改成参考演示的64×28/40×24。

## 静态配色和层级

| 项目 | 浅色 | 深色 |
| --- | --- | --- |
| 开启轨道 | 主题accent/primary，alpha0.74 | 主题accent/primary，alpha0.64 |
| 关闭轨道RGBA | 255/255/255/0.46 | 255/255/255/0.12 |
| 默认滑块 | 白色，alpha按0.92−0.72p变化 | 白色，alpha按0.92−0.72p变化 |

轨道复用Button角色的玻璃绘制：静态p=0、blur8、edge12、amount16、shadow6、轮廓强度0.5、外缘宽0.5，外阴影alpha浅0.08/深0.18。不叠加实体边框或旧实色灰/绿底；宿主默认accent RGB71/111/232可由主题覆盖。先用外部背景绘制玻璃轨道，再将轨道录制为滑块的独立取样源，绝不采样滑块自身。显式自定义颜色保持原值；无对应参数的平台不能虚构公开参数。

绘制顺序：背景源 + 轨道源 → Clamp模糊 → 圆弧折射及色散 → 白色滑块表面 → Ambient高光 → 内阴影。外阴影在表面后方。整条开关不执行普通按钮的0.975缩放或0.92透明度，弹性只作用于滑块的绘制层。

## 五条动效通道

| 通道 | 目标与参数 |
| --- | --- |
| 位置x | 目标限制[0,1]；dampingRatio1、stiffness1000、阈值0.001 |
| 按压p | active时1，否则0；1/1000、阈值0.001 |
| 横向伸缩sx | active时1.5，否则1；0.6/250、阈值0.001 |
| 纵向伸缩sy | active时1.5，否则1；0.7/250、阈值0.001 |
| 速度v | 对位置样本使用VelocityTracker估计，每秒的归一化行程；0.5/300平滑，阈值0.01 |

active = 可用 且（正在按下 或 abs(当前位置−目标位置)≥0.025）。松开当帧不能直接缩回，位置接近目标后才释放p/sx/sy。点击、拖动吸附和外部受控值变化都使用这一完整链路，快速反向从当前值和速度继续，不从端点重新开始。

最终scaleX = sx / (1 − clamp(v/50 ×0.75,−0.2,0.2))。

最终scaleY = sy × (1 − clamp(v/50 ×0.25,−0.2,0.2))。

不得漏掉VelocityTracker、用位移直接当速度、将50改为TabBar的10，或将1.5改为TabBar的78/56。Flutter映射mass=1、damping=2×dampingRatio×sqrt(stiffness)，使用框架速度采样器；不同框架的速度估计与帧调度应实测，不凭参数一致宣称逐帧像素等同。

## 材质随p的连续变化

| 项目 | 精确值 |
| --- | --- |
| blur | 8×(1−p) |
| lens边缘 | 5p |
| lens位移 | 10p，向内折射 |
| chromaticAberration | lens启用时固定1；不是p |
| 表面白色/显式底色alpha | 原alpha×(0.92−0.72p)，按住保留0.2底面 |
| 轨道采样scaleX | 2/3+p/12 |
| 轨道采样scaleY | 0.75p |
| 滑块外阴影 | 黑色alpha浅0.08/深0.18、radius4、offset(0,4/6) |
| 内阴影 | 黑色alpha0.15p、radius4p、offset(0,4p) |

Switch滑块的第一个Clamp blur不扩展采样画布，因此滑块采样padding=0；玻璃轨道采用Button的ceil(blur×3+edge)范围，不能把二者混用。先录制背景，再叠加独立玻璃轨道，只对轨道采样副本缩放；p=0时轨道Y采样为0，不应导致非法矩阵或整块采样失败。

保留完整源到目标坐标变换。滑块扩张时不能只减源/目标平移量，否则背景放大错位；不得把镜片自身录入其背景源。七波段的偏移和RGB/alpha权重逐式使用包内着色器。

## Ambient：不是白色渐变边框

位置先转换到当前圆角轮廓的中心坐标，再计算圆角矩形距离场梯度n。d = dot(n,(cos45°,sin45°))；颜色为(t,t,t,1)×abs(d)，t=step(0,d)。这会同时形成方向相关的黑/白边缘，不能替换成全白轮廓或按钮的三段渐变。

基础强度0.38、宽度0.5/1.5dp、遮罩模糊0.25/1.5dp；轮廓实际描边宽为ceil(width×density)×2个物理像素，由圆角裁去外半边。保留参考的像素取整，不能把逻辑宽写死为2。

先对描边覆盖遮罩模糊，再按法线着色，整体alpha乘p；不要把已经着色的黑白结果整体模糊。内阴影在Ambient之上，按原轮廓填充黑色，再清除向下4p偏移的轮廓，对遮罩做4p模糊并裁入原形状。Kotlin的HyperSwitchHighlight和Flutter的HyperSwitchEdgePainter分别实现这一流程。

## 手势和状态

- 首根指针按下立即开始反馈。横向移动立即更新临时目标，不额外等待touchSlop；RTL反转delta方向，目标=clamp(起始目标+deltaX/20×方向,0,1)。只跟踪当前指针，不叠加多指输入。
- Compose必须依次经过同一次down的Initial和Main阶段，再开始读取move；clickable消费Main down是正常行为，不能因此退出拖动协程。仅后续移动被其他手势消费时才取消。遗漏这一步会出现按住高光正常、但持续拖动无效的缺陷。
- 点击松手请求取反；横向拖动松手以临时目标≥0.5请求开启，否则关闭，一次提交。拖动期间不提交业务状态，父标签行不能同时再提交点击。
- 取消、纵向滚动接管或失去可用性恢复受控值，不提交。该取消语义是宿主受控组件的保留边界，不能复制参考演示中取消也调用onDragStopped的副作用。
- 标签行仍是plain行，只保留现有标签、禁用及点击布局。禁用/onChanged为空不交互，沿用静态弱化分支；参考演示没有禁用API，不能将其当成可交互实现来覆盖宿主。
- 减少动态效果遵守宿主分支：Flutter直接定位且scale=1；Android/Compose遵守系统动画时长。不得为了复现普通动效移除无障碍设置。

## 验证重点

同一背景、主题、字体、密度和帧率下核对：关闭/开启静态色；按住的扩张、透明底色、Ambient与折射；点击与快速反向的速度形变；按住至少1秒不松、缓慢拖到行程中部并停住、继续拖向另一侧、原路反向且仍不松手、最后释放；拖到阈值两侧再释放；拖动取消；RTL；禁用；外部值变化；标签行单次回调；减少动态效果。必须在手指未松开时确认中间位置和轨道颜色确实变化；只看拖动前后开/关状态，无法区分真正拖动与被误触发的一次点击。缩放过程要查看阴影和背景坐标，不只看位置终点。

本包的验收对象是当前共用玻璃皮肤与完整交互基线。只有完成相同运行环境的动态对照，才能宣称动态视觉一致；源码、数值和哈希校验不能替代逐帧验收。
